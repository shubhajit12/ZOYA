IMPORTANT BONE OWNERSHIP:

The existing Carlotta procedural body controller currently owns its existing body bones.

Do NOT create competing writers for those bones.

The gesture layer should be explicitly isolated to the reserved ARM/gesture bones.

Before implementing, inspect the actual Carlotta humanoid bone availability and determine which arm/hand bones are safe to use.

Do NOT assume bones exist.

Gracefully degrade when a bone is missing.

GESTURE BEHAVIOR:

Gestures should NOT loop forever.

Example:

wave:
start → raise arm → wave → lower arm → complete

bow:
start → bow → hold briefly → return → complete

clap:
start → bring hands together → clap → separate → complete

point:
start → raise arm → point → hold → return

shrug:
start → raise shoulders/arms → hold → return

Each gesture needs:

* deterministic timing
* smooth interpolation
* easing
* start/active/recovery phases
* completion state
* cancellation support
* no accumulated quaternion drift
* no per-frame allocations

GESTURE PRIORITY:

Define clear rules.

Example:

Higher priority:
explicit gesture

Lower priority:
idle

Emotion/state layers must not permanently overwrite an active gesture.

After a gesture finishes, the normal idle/talking/listening/emotion state should automatically resume.

INTERRUPTION:

A new explicit gesture should be able to cancel/replace an existing gesture cleanly.

Talking/listening should NOT randomly cancel gestures.

If necessary, use a small priority system such as:

idle < state < emotion < gesture

BUT do not blindly apply this if it conflicts with existing controller ownership. Inspect the current implementation first and choose the safest architecture.
