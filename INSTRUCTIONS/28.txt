* Carlotta textures/materials

---

# GOAL

Add a user-accessible performance quality system:

**Settings → Performance → Quality**

Available modes:

1. **Auto**
2. **High**
3. **Medium**
4. **Low**

On the user's FIRST launch:

* Quality should default to `Auto`.
* Perform a lightweight device capability check.
* Automatically select an appropriate starting quality internally.
* Store the selected result locally.
* Do NOT repeatedly override the user's choice after they manually change it.

The user must always be able to manually choose High / Medium / Low.

Do not create an overly complicated benchmark system yet.

---

# IMPORTANT DISTINCTION

There are two concepts:

### User setting

`Auto | High | Medium | Low`

### Effective runtime quality

The actual profile currently being used:

`High | Medium | Low`

If the user selects `Auto`, the system determines the effective quality.

If the user manually selects High/Medium/Low, respect that choice.

---

# FIRST-LAUNCH AUTO DETECTION

Create a lightweight capability detector.

Use information that is safely available in the browser/renderer, such as:

* WebGL/WebGL2 availability
* renderer/GPU information where safely available
* devicePixelRatio
* screen/canvas resolution
* available hardware concurrency where available
* other non-invasive renderer capability information

Do NOT perform a long benchmark.

Do NOT intentionally stress the GPU.

Do NOT allocate large temporary textures.

The detector should simply estimate:

* High-capability device
* Medium-capability device
* Low-capability device

Use conservative thresholds.

If information is unavailable, choose Medium rather than making an aggressive assumption.

---

# QUALITY PROFILES

Create one centralized quality configuration/profile system.

Do not scatter quality constants throughout the renderer.

Use approximately these starting profiles:

## HIGH

* pixel ratio cap: `2.0`
* antialias: ON
* shadow maps: OFF unless the current scene actually gains from them
* spring bones: full
* render target: normal/full quality
* future texture quality: full

## MEDIUM

* pixel ratio cap: `1.25`
* antialias: OFF
* shadow maps: OFF
* spring bones: full initially
* render target: normal
* future texture quality: medium

## LOW

* pixel ratio cap: `1.0`
* antialias: OFF
* shadow maps: OFF
* spring bones: reduced quality can be supported by the profile, BUT DO NOT MODIFY SPRING-BONE BEHAVIOR IN THIS TASK
* render target: normal
* future texture quality: low

IMPORTANT:

For this task, only actually apply renderer settings that are safe with the current renderer architecture.

Do NOT modify spring-bone behavior yet.

Do NOT modify textures yet.

Those are future optimization phases.

# RENDERER REQUIREMENT

The current audit showed that:

* Carlotta is ~72k triangles
* geometry is NOT the primary bottleneck
* textures are the largest asset memory consumer
* pixel ratio + MSAA can create significant GPU/fill pressure
* there are currently no actual shadow casters

Therefore the first renderer-level quality controls should focus on:

1. pixel ratio
2. antialiasing
3. shadow map state

The effective pixel ratio must never exceed the selected profile's cap.

For example:

```ts
renderer.setPixelRatio(
    Math.min(window.devicePixelRatio || 1, profile.pixelRatioCap)
);
```

Make sure resize handling continues respecting the cap.

---

# ANTIALIASING

Antialiasing is determined when `WebGLRenderer` is created.

DO NOT attempt to simply toggle:

```ts
renderer.antialias
```

after creation.

Inspect the current renderer initialization.

If the current architecture cannot safely change antialiasing at runtime, do NOT introduce a risky renderer recreation system just for this phase.

Instead:

* apply the selected quality profile during renderer initialization
* make first-launch Auto selection available before renderer creation if possible
* if the existing architecture makes that impossible, preserve stability and document that antialias changes require renderer recreation/reload

Do not break the renderer.

---

# SHADOW MAP

The audit found:

* shadow maps are enabled in renderer code
* no lights currently appear to have `castShadow=true`
* therefore there is likely no useful shadow pass

Safely disable:

```ts
renderer.shadowMap.enabled = false;
```

for the current Carlotta path.

Do not modify lighting appearance.

Do not remove lights.

Do not modify materials.

# USER OVERRIDE BEHAVIOR

Example:

First launch:

```text
Quality = Auto
Detected = Medium
Effective = Medium
```

User changes:

```text
Quality = High
```

Then:

```text
Effective = High
```

The app must NOT silently switch them back to Medium.

If the user later selects:

```text
Quality = Auto
```

automatic detection becomes active again.

---

# RESIZE BEHAVIOR

Whenever the canvas/container is resized:

* preserve the selected quality pixel-ratio cap
* never accidentally restore uncapped `devicePixelRatio`
* do not change camera FOV
* do not change camera position
* do not change OrbitControls

# MOBILE-FIRST DESIGN

This system is being introduced because Zoya must eventually run on mobile hardware.

Do not assume desktop GPU capability.

The architecture should make it easy to add future controls such as:

* texture quality
* spring-bone quality
* render frequency
* adaptive performance
* battery-saving mode

But DO NOT implement those systems yet unless they already exist.

Keep the profile structure extensible.
