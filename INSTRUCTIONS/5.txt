## Confirmed bug

The current test correctly does:

CLOSED → 25% → 50% → 75% → 100% → CLOSED

and the `_mouthPoseLastAppliedPhase` guard has already eliminated the per-frame logging/measurement spam.

However, after reaching the final CLOSED stage, the test starts another cycle forever.

The cause is the ordering inside `runMouthPoseTest()`:

1. Final `open100` sets:
   `_finishAfterClosed = true`
   `_mouthPoseTimer = 0`
   `_mouthPosePhase = "closed"`

2. During the final CLOSED hold, when `_mouthPoseTimer >= HOLD`, the normal phase-advance `if` executes first.

3. It resets the timer and advances:
   `closed → open25`

4. Therefore the later stop condition never sees `_mouthPoseTimer >= HOLD`.

## Required fix

Change ONLY the ordering/logic in `runMouthPoseTest()` so that:

* If `_mouthPosePhase === "closed"`
* AND `_finishAfterClosed === true`
* AND `_mouthPoseTimer >= HOLD`

then the test MUST STOP immediately.

The stop check must happen BEFORE the normal `closed → open25` phase-advance logic.

On stopping:

* Set `_mouthPoseTestActive = false`
* Set `_sweepActive = false` if that is the existing intended completion behavior
* Clear/consume `_finishAfterClosed`
* Keep Mint in the CLOSED pose
* Do NOT start another cycle
