## UPGRADE MINT: EMOTION-AWARE BODY POSTURE

We now have a working facial emotion system and a procedural body animation controller.

The facial emotions visually look good. **Do not modify or retune the facial expression system.**

Your task is to add a subtle, persistent **emotion-aware body posture layer** to the existing `CarlottaAnimationController`.

### HARD CONSTRAINTS

DO NOT:

* use Mixamo
* add animation files
* add AnimationMixer
* add animation clips
* replace the VRM/model
* replace the skeleton
* modify mesh vertices
* modify textures/materials
* change camera
* change OrbitControls
* change Groq
* change TTS
* change lip-sync
* change the existing facial expression recipes/mappings
* create a second body animation controller
* create another per-frame bone writer
* accumulate bone rotations
* use `bone.rotation.x += ...` or equivalent cumulative rotation
* alter the existing relaxed/base pose
* break existing idle/talking/listening/thinking behavior

Keep the implementation lightweight and suitable for low-end PCs.

---

# GOAL

Make Mint's **body language naturally reflect the current emotion** while preserving the existing behavior state.

The architecture should become:

Emotion
↓
Facial emotion system
+
Emotion-aware body posture layer
↓
Existing procedural behavior state
↓
Final body pose

Emotion and behavior MUST remain independent.

Examples:

```text
Emotion = happy
State = talking

→ happy posture
→ talking movement
→ happy facial expression
```

```text
Emotion = sad
State = listening

→ sad posture
→ listening movement
→ sad facial expression
```

Do NOT replace one state with another.


Do NOT create a second emotion state.

Emotion transitions must remain smooth.

# POSTURE DESIGN

Implement subtle procedural posture offsets.

These are NOT rigid poses. They should feel like natural body language.

## CALM

Baseline / relaxed posture.

* relaxed shoulders
* neutral chest
* neutral head
* gentle breathing
* essentially the existing idle posture

Do not disturb the current idle behavior.

## HAPPY

Subtle open/confident body language.

* slightly lifted chest
* shoulders slightly more open
* very subtle upward head tendency
* tiny positive weight shift
* maintain relaxed shoulders

Keep it subtle.

## EXCITED

More energetic version of happy.

* slightly more upright chest
* slightly elevated shoulders
* slightly larger natural weight shifts
* slightly more energetic head movement
* preserve existing breathing

Still believable, NOT exaggerated.

## SAD

Subtle closed/downward posture.

* chest slightly lowered
* shoulders slightly lowered/forward
* head slightly lowered
* reduced weight-shift amplitude
* slightly softer movement

Do not make the character collapse or slump dramatically.

## ANGRY

Subtle controlled tension.

* chest slightly more upright
* shoulders slightly firmer
* head more stable
* reduced loose weight shifting
* subtle torso/shoulder tension

Do NOT create an exaggerated fighting pose.

# LAYERING

The emotion posture layer must coexist with:

```text
idle
talking
listening
thinking
```

The final pose should be calculated from the original captured base quaternions.

Conceptually:

```text
base quaternion
    +
idle/body behavior offset
    +
emotion posture offset
    =
final quaternion
```

Do NOT apply an emotion rotation on top of the previous frame's already modified rotation.

No accumulation.

---

# SMOOTHING

Emotion posture must smoothly interpolate using the existing emotion transition system.

When transitioning:

```text
calm → happy
```

the posture should gradually change.

When transitioning:

```text
happy → sad
```

the posture should gradually move toward sad.

No snapping.

Intensity must scale the posture:

```text
intensity = 0
→ no emotion posture

intensity = 0.5
→ half strength

intensity = 1
→ full strength
```

---

# SYMMETRY

Avoid making the character look unnaturally crooked.

Use mostly symmetrical posture offsets.

Tiny asymmetry/weight shifts are acceptable only if they already exist in the procedural behavior system.

---

# PERFORMANCE

Do not allocate objects every frame.

Reuse temporary quaternions/vectors.

Keep calculations lightweight.

Do not introduce expensive IK, physics, or procedural skeletal solving.
